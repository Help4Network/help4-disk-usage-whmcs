# Security Policy

Development preview. Native WHMCS/framework/MySQL/TLS/role and matching panel acceptance remain required before stable promotion. Source extraction, checksums and synthetic CI are not certification. Report vulnerabilities privately; never attach customer paths, credentials or production captures to public issues.

- Preserve both addon IDs and separate table namespaces. cPanel never adopts a Plesk mapping, transport or Windows deployment target.
- Current authenticated WHMCS User, selected Client Account, permissions and active service/server authorize customer data. Stored client IDs are not current entitlement. Preserve role/impersonation checks and generic foreign/stale mapping refusals.
- Administrative changes require native role/access controls, POST and CSRF. Passive health must not silently collect a fleet, deploy, reconnect, repair mappings or repin identity.
- Keep independently verified SSH pins and authenticated HTTPS peer/hostname verification fail-closed. No unpinned/TLS bypass, arbitrary redirects, printed credentials or paths used as endpoints.
- Plesk install/subscription GUID/owner/name/home bindings stay current around IO. Native MySQL Connect/Approve/Disconnect serialization is separate from SQLite fixture coverage.
- Preserve one-at-a-time transport/scanning and finite runtime/output/queue/server/user/subscription budgets. Failures consume admitted attempts where required; unknown measurements are not healthy-zero.
- Native roots/executables remain SDK/operator controlled. No arbitrary-root endpoint, customer-selected executable, file-content/deletion API, login minting or unattended addon installation.
- Keep templates escaped, CSV formula-neutralized, reports private/scoped, native navigation fixed/current and the small linked Help4 byline visible.
- Package only the explicit WHMCS runtime/public-doc inventory. Exclude native source, tests, reports, evidence and secrets. Verify outer and inner checksums from reviewed quiescent source.

Native files under tests/fixtures/plesk are read-only protocol fixtures, not installation payloads. Upstream changes require explicit protocol/fixture review. Native session caching, HTTP behavior, effective Windows ACLs, scheduler/lifecycle and continuously atomic authorization remain separate gates. Existing source coverage is not a completed native security audit.
